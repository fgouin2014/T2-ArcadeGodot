# Instructions GitHub Copilot - Projet Godot Engine

## 🎮 Contexte du Projet
- **Moteur de jeu** : Godot Engine v4.x (GDScript)
- **Type de jeu** : Remake du jeu d'arcade "Terminator 2: The Arcade Game" (1991) par Midway Games. DOS/PC version.
- **Origine du code** : Code hérité d'un outil externe. Prioriser la refactorisation propre, les performances de la boucle de jeu (`_process` / `_physics_process`) et l'organisation des nœuds.

## 🏗️ Règles de Style et Conventions GDScript (Godot 4)
- **Typage statique** : Toujours utiliser le typage statique strict (ex: `var score: int = 0` ou `func get_damage() -> int:`). Éviter le typage dynamique.
- **Accès aux nœuds** : Utiliser la notation abrégée `@onready var mon_noeud = $MonNoeud` ou `%MonNoeud` pour les nœuds uniques de la scène.
- **Style de nommage** : 
  - `snake_case` pour les fonctions, variables et noms de fichiers (ex: `player_controller.gd`).
  - `PascalCase` pour les classes (`class_name Player`).
  - `UPPERCASE` pour les constantes (`const MAX_SPEED = 300.0`).
- **Signaux** : Préférer la connexion des signaux par code via la syntaxe Godot 4 (ex: `button.pressed.connect(_on_button_pressed)`).

## 🤖 Directives pour l'Agent (Copilot Edits / @workspace)
- **Gestion des ressources** : Ne modifie jamais manuellement les fichiers `.tscn` (scènes) ou `.godot` sauf demande explicite. Concentre-toi uniquement sur les scripts `.gd`.
- **Mémoire** : Assure-toi que les objets créés dynamiquement (via `.new()` ou `instantiate()`) sont libérés correctement avec `queue_free()` si nécessaire.

## 🚫 Restrictions (Ne pas faire)
- Ne jamais analyser ni modifier le dossier caché `.godot/` (cache et importations).
- Éviter d'utiliser `get_node()` de manière répétée dans la boucle `_process` ou `_physics_process` (privilégier les variables `@onready`).
